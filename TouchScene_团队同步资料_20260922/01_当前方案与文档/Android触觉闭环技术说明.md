# TouchScene 安卓触觉闭环 Demo

## 结论

安卓端建议保留两级实现：

1. **PWA / Chrome 手机振动**：零外接硬件，用于当天验证交互和触觉编码；
2. **Web Bluetooth + ESP32-C3 + 振动马达**：用于验证外接执行器、协议闭环和延迟。

两条路线共用同一张 `64×48` 触觉地图和同一套坐标映射，因此切换输出设备不会改变图像处理结果。

## 1. 安卓手机如何直接振动

### 网页 / PWA

安卓 Chrome 可调用：

```js
navigator.vibrate(40);             // 单次 40 ms
navigator.vibrate([30, 35, 30]);   // 双脉冲
navigator.vibrate(0);              // 停止
```

限制：

- 必须由用户先点击或触摸页面，建立 user activation；
- 静音、勿扰模式或系统振动设置可能阻止反馈；
- Web API 只能稳定表达“开/关和节奏”，不能保证不同安卓机型具有一致的振幅；
- 新振动会终止旧振动，因此应用必须做节流，不能对每个 `pointermove` 都无脑重放；
- 页面进入后台时不应继续把振动当作可靠输出。

本 Demo 的编码：主体内部 22 ms 轻脉冲；轮廓 42 ms 强脉冲；关键点 `32-34-32 ms` 双脉冲。

### 原生 Android

如果后续要封装 APK，应使用 `VibratorManager`（Android 12 / API 31+）和 `VibrationEffect`：

```xml
<uses-permission android:name="android.permission.VIBRATE" />
```

```kotlin
val manager = getSystemService(VibratorManager::class.java)
val vibrator = manager.defaultVibrator
vibrator.vibrate(VibrationEffect.createPredefined(VibrationEffect.EFFECT_CLICK))
```

需要振幅时先检查 `vibrator.hasAmplitudeControl()`；不支持的手机会把非零振幅近似为全强度，因此仍需提供节奏型降级。

## 2. ESP32 BLE 外接闭环

### 硬件

- ESP32-C3 SuperMini；
- 5 V 扁平振动马达；
- AO3400 逻辑电平 MOSFET；
- 100 Ω 栅极电阻、10 kΩ 栅极下拉；
- SS14/1N5819 续流二极管；
- 5 V 独立供电，电源地与 ESP32 共地。
- 可选 SW-420 振动传感器模块（用于比赛演示时证明马达真的产生了振动）。

不得从 GPIO 直接驱动马达。

### GATT

| 项目 | UUID / 作用 |
|---|---|
| Service | `7b100001-6c7d-4c7a-9a31-54bf3f010001` |
| Command | `...0002`，网页 Write With Response |
| ACK | `...0003`，ESP32 Notify |

命令固定 10 字节：

| 字节 | 内容 |
|---:|---|
| 0 | `0xA1` 协议标记 |
| 1 | `seq`，0～255 循环序号 |
| 2 | `mode`：0 背景、1 主体、2 轮廓、3 关键点 |
| 3～4 | X 坐标，小端序 |
| 5～6 | Y 坐标，小端序 |
| 7 | 强度提示 0～255 |
| 8 | 持续时间，单位 10 ms |
| 9 | 前 9 字节 XOR 校验 |

ESP32 返回 9 字节 ACK，原样带回 `seq/mode/x/y`。网页分别显示“坐标 ACK 一致”和执行器反馈，避免把软件执行误报成物理振动。

ACK 状态码：

| 状态 | 含义 |
|---:|---|
| 0 | GPIO 状态已应用，但未启用物理传感器 |
| 1 | 数据包或校验码无效 |
| 2 | 触觉模式无效 |
| 3 | SW-420 在确认窗口内检测到实际振动 |
| 4 | 坐标和模式正确，但未检测到物理振动 |

不装传感器时，状态 0 只能证明触摸坐标、图像状态和 ESP32 GPIO 输出一致。装上 SW-420 后，状态 3 才代表物理马达闭环成立；状态 4 会在页面明确标红。

### 可选物理反馈接线

完整图示见 [`dist/touchpuck/wiring.svg`](../dist/touchpuck/wiring.svg)，在线 Demo 的 ESP32 BLE 面板也可直接展开查看。

- SW-420 `VCC` → ESP32-C3 `3V3`
- SW-420 `GND` → 公共地
- SW-420 `DO` → GPIO 5
- 将模块紧贴马达外壳，调电位器到“马达启动可靠触发、桌面轻触不误触”
- 把固件顶部 `ENABLE_VIBRATION_SENSOR` 从 `0` 改为 `1` 后重新烧录

固件会在启动马达前采集传感器静止电平，因此兼容“振动输出 HIGH”和“振动输出 LOW”的不同模块批次；GPIO 中断会锁存很短的脉冲，8 ms 后再判定，并在 160 ms 窗口内寻找相对静止电平的变化。检测成功回传状态 3；超时回传状态 4。停止命令仍返回状态 0，因为“没有振动”不能由该开关模块在单次 ACK 内可靠证明。

### 防止错位和积压

- 触屏本身给出绝对坐标，不使用鼠标相对位移，因此不会累计漂移；
- 触点坐标按画布实际边界归一化，再映射到 `64×48` 网格；
- BLE 同一时刻只允许一个写请求在途，新移动只保留最新坐标；
- 手指停留时每 180 ms 发送 keepalive，使 ESP32 的 600 ms 安全看门狗不会误停；
- 断连、ACK 超时或页面抬指时发送/进入背景状态，马达停止；
- 视觉处理和触觉查询均在手机本地执行，不依赖网络往返。

## 3. 使用步骤

### 手机振动

1. 用安卓 Chrome 打开 HTTPS Demo；
2. 选择“手机振动”；
3. 点击“运行手机三段自检”；
4. 打开相机拍摄高对比物体，或先使用内置圆形/三角形；
5. 在右侧触觉画布按住并滑动；
6. 检查背景、主体、轮廓是否能被稳定区分。

### BLE

1. 连接 ESP32-C3 后，在项目根目录运行 `powershell -ExecutionPolicy Bypass -File scripts/touchpuck-commission.ps1`；需要 SW-420 物理确认时追加 `-EnableSensor`。脚本只自动选择 USB 串口，不会误选蓝牙 COM 口；有多个 USB 串口时追加 `-Port COMx`；
2. 接好 MOSFET、续流二极管、马达和独立 5 V 电源；
3. 若需要物理闭环证明，接入 SW-420、启用固件开关并调好灵敏度；
4. 在安卓 Chrome Demo 中选择“ESP32 BLE”；
5. 点击“连接 TouchPuck”，在系统选择器中选择 `TouchPuck-Haptic`；
6. 先运行 BLE 四状态自检；
7. 在画布滑动，确认“坐标 ACK 一致”和“物理振动已检测”同时出现。
8. 点击“运行 100 点硬件验收”，等待页面给出映射成功率和物理确认率；启用传感器时门槛为映射 100/100、物理确认至少 99/100。
9. 点击“下载验收报告 JSON”，保存每条命令的坐标、模式、ACK 状态和 RTT，作为现场演示证据。

Web Bluetooth 要求 HTTPS，并且设备选择器必须由用户点击触发。Android Chrome 支持该能力；不应把 iOS Safari 作为该网页 BLE 路线的目标。

## 4. 测试门槛

| 测试 | 通过门槛 |
|---|---|
| 协议编码/解码 | 坐标、模式、序号往返完全一致 |
| CRC/XOR 故障注入 | 任意数据位破坏必须被拒绝 |
| BLE 映射 | 连续 100 个点无坐标/模式错配 |
| 物理执行 | 非背景命令 100 次中 ≥ 99 次返回状态 3，禁止把状态 0 当成物理确认 |
| BLE 延迟 | 平均 RTT < 80 ms，P95 < 150 ms |
| 断连安全 | 断连后 600 ms 内马达停止 |
| 手机触觉 | 圆/三角/矩形闭眼识别率 ≥ 80% |
| 热稳定 | 10 分钟探索无 MOSFET、马达或电源异常发热 |

## 5. 当前已验证与仍需实测

已自动验证：坐标边界映射、命令往返、ACK 往返、校验损坏拒绝、图像填充/轮廓分类、延迟统计。
